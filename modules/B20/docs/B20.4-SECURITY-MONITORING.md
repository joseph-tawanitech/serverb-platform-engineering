# B20.4 — Security Monitoring

**Status:** PASS

B20.4 establishes the security monitoring contract and monitoring-to-evidence integration layer for TAP B20.

## Purpose

B20.4 provides a provider-neutral contract for security observations produced by monitoring systems and converts those observations into the normalized `SecurityEvidence` contract established by B20.3.

The monitoring layer does not replace monitoring systems. Prometheus, Kubernetes, OpenTelemetry, Linux, Windows, logs, network/security systems, identity systems, cloud infrastructure, and other authorized sources remain responsible for producing observations.

TAP B20 provides the common security representation consumed by downstream investigation and AI security operations.

## Monitoring Contract

`SecurityObservation` captures:

- observation identity
- source
- environment
- asset
- observation
- category
- severity
- monitoring data
- UTC timestamp

## Monitoring → Evidence

B20.4 provides `observation_to_evidence()` to convert a `SecurityObservation` into the B20.3 `SecurityEvidence` contract.

The adapter preserves:

- source
- environment
- asset
- observation
- category
- severity
- monitoring data
- policy reference
- risk
- provenance
- observation identity

```text
Monitoring Source
       ↓
SecurityObservation
       ↓
B20.4 Monitoring Adapter
       ↓
B20.3 SecurityEvidence
       ↓
Investigation / AI Security Operator

## Architectural Role

B20.4 is provider-neutral and does not depend on a specific AI model.

The monitoring system establishes observations.

B20.3 establishes normalized security evidence.

Future MCP integration can expose authorized current evidence to AI.

B19 RAG can provide relevant security knowledge, policies, runbooks, historical incidents, and previous investigation context.

The AI Security Operator can then investigate and reason over the combined context.

TAP policy and authorization remain responsible for governing security actions.

## Repository Packaging

B20 is packaged through `modules/B20/pyproject.toml` so the component can be installed reproducibly from the repository rather than depending on a manually configured `PYTHONPATH`.

The package can be installed in editable mode during local development:

```text
python -m pip install -e modules/B20
```

Generated installation metadata such as `*.egg-info` is not part of the repository source.

## Design Principle

**Monitoring detects. Observability exposes system behavior. Evidence establishes what happened. RAG supplies relevant knowledge. AI investigates and reasons. TAP governs decisions and authority. Automation executes. Verification proves the result.**

B20.4 specifically provides the monitoring-to-evidence boundary needed for that lifecycle.
