# B20.3 — Security Evidence

**Status:** PASS

B20.3 establishes the normalized security evidence layer for TAP B20.

The SecurityEvidence contract captures:

- evidence identity
- source
- environment
- asset
- observation
- category
- severity
- evidence payload
- policy reference
- risk
- provenance
- UTC timestamp

B20.3 also provides an evidence normalizer that converts security observations from different sources into the common TAP SecurityEvidence contract.

## Architectural Role

B20.3 separates security evidence collection from AI reasoning.

Security sources may include Linux, Windows, Kubernetes, network systems, identity systems, cloud infrastructure, monitoring systems, logs, and MCP collectors.

Sources produce observations. The B20 evidence layer normalizes those observations so downstream investigation and AI security operations can consume a consistent structure.

## Design Principle

B20.3 is provider-neutral.

Evidence is established independently of the AI model. Claude, GPT-6, Qwen, Grok, or another model may consume the evidence later, but the evidence contract remains controlled by TAP.

## Security Flow

Security Source → Observation → Evidence Normalizer → SecurityEvidence → Investigation → AI Security Operator → Policy → Governed Action
