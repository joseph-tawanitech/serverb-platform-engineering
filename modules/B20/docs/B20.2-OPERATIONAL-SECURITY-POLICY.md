# B20.2 — Operational Security Policy

**Status:** PASS

B20.2 establishes the deterministic operational security policy layer for TAP B20.

The policy defines:
- authorized environment and assets
- allowed operations
- operations requiring review
- explicitly blocked operations
- policy version and identity
- configured maximum risk
- enabled/disabled policy state

Policy evaluation produces one of three decisions:

- ALLOW — the operation is permitted by policy
- REVIEW — the operation requires further review
- BLOCK — the operation is outside the permitted policy boundary

B20.2 does not itself grant execution authority. TAP authorization and execution controls remain responsible for determining whether an approved operation may actually execute.

The evaluator uses conservative behavior:
- disabled policy → REVIEW
- wrong environment → BLOCK
- unauthorized asset → BLOCK
- blocked operation → BLOCK
- review operation → REVIEW
- allowed operation → ALLOW
- unknown operation → REVIEW

## Architectural Role

B20.2 provides the policy boundary between AI/security recommendations and governed TAP operations.

AI may recommend a security action, but the policy layer determines whether that requested operation is permitted, requires review, or is blocked. Execution authority remains outside the policy evaluator.
