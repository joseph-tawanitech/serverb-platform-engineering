**Module:** B19 — Retrieval-Augmented Generation (RAG)
**Phase:** B19.9
**Status:** PASS

**Architecture Role:** Knowledge-to-AI boundary

---

## 1. Purpose

B19.9 establishes the **RAG Context Assembly & AI-Ready Knowledge Packaging** layer between knowledge retrieval and future AI investigation.

B19.8 answers:

> **Which knowledge is relevant?**

B19.9 answers:

> **How should the retrieved knowledge be structured and presented to future AI reasoning?**

The purpose of B19.9 is to transform deterministic B19.8 retrieval results into a structured, validated, bounded, provider-neutral `RAGContext`.

B19.9 prepares knowledge for future AI consumption without performing AI reasoning itself.

### Core principle

> **Context prepares knowledge for reasoning; it does not perform the reasoning.**

B19.9 sits directly after retrieval and ranking.

```text
B18 Incident Evidence

        │
        ▼

        │
        │ Relevant knowledge
        ▼
B19.9 Context Assembly
        │
        │ Structured RAG Context
        ▼
Future AI Investigation / RCA
        │
        ▼
AI Recommendation
        │
        ▼
TAP Governance
        │
        ▼
Authorization → Execution → Verification
```

B19.9 therefore forms an important architectural boundary between:

* deterministic knowledge retrieval
* future AI reasoning

The AI model does not directly control the retrieval layer.

The retrieval layer does not perform AI reasoning.

The context layer packages the retrieved knowledge into a controlled structure that future AI components can consume.

# 5. RAGContextItem

`RAGContextItem` represents one retrieved knowledge item packaged for future AI consumption.

It preserves the important information produced by B19.8.

### Fields

```text
rank
document_id
title
score
score_breakdown
knowledge_type
source_type
resource
tags
source
provenance_reference
provenance_version
provenance_checksum
provenance_collected_at
provenance_collector
```

### Architectural purpose

The context item preserves both:

1. **relevance information**
2. **traceability information**

The future AI consumer can therefore receive not only a knowledge item, but also information describing why the item was retrieved and where it originated.

---

# 6. Relevance Preservation

B19.9 preserves the B19.8 relevance score.

For example:

```text
score = 80
```

and the associated score breakdown:

```text
resource
knowledge_type
source_type
tag
title
```

are preserved.

The context assembler does not recalculate or reinterpret the relevance score.

This is intentional.

B19.8 owns retrieval and ranking.

B19.9 owns context packaging.

Therefore:

> **B19.9 does not become a second ranking engine.**

---

# 7. Provenance Preservation

B19.9 preserves the provenance information established by B19.7 and carried through B19.8.

The following fields are preserved:

```text
provenance_reference
provenance_version
provenance_checksum
provenance_collected_at
provenance_collector
```

This maintains the traceability chain:

```text
Knowledge Source
      ↓
Provenance
      ↓
Knowledge Document
      ↓
Evidence Index
      ↓
Retrieval Result
      ↓
RAG Context
      ↓
Future AI Reasoning
```

This is important for AI-SRE because future reasoning must be able to distinguish:

* what knowledge was retrieved
* where it came from
* when it was collected
* which collector produced it
* which integrity information is associated with it

# 8. Query Preservation

B19.9 preserves the original retrieval query information.

`RAGContext` contains:

```text
context_id
query_id
query_text
```

This provides traceability between the assembled context and the retrieval request that produced it.

The relationship is:

```text
Query
  ↓
Retrieval
  ↓
Ranking
  ↓
Context Assembly
```

The query therefore remains attached to the resulting context.

This will become important for future AI investigation auditing.

---

# 9. Context Ordering

Context items receive deterministic sequential ranks.

Example:

```text
Rank 1 → highest-ranked retrieval result
Rank 2 → second-ranked retrieval result
Rank 3 → third-ranked retrieval result
```

The assembler assigns ranks based on the order of the B19.8 retrieval results.

The resulting context therefore has a deterministic structure:

```text
RAGContext
├── Item 1
├── Item 2
├── Item 3
└── ...
```

The context validator requires ranks to be sequential.

For example:

```text
1
2
3
```

is valid.

But:

```text
1
3
4
```

is rejected.

---

# 10. Context Size Control

B19.9 introduces an explicit `max_items` control.

The context assembler supports:

```text
max_items
```

to limit the number of retrieved results included in the final context.

The following rule is enforced:

```text
max_items <= query.limit
```

This prevents B19.9 from silently expanding the retrieval boundary established by the query.
