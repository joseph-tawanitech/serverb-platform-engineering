## 1. Purpose

B19.11 establishes the controlled boundary between the deterministic RAG context contract and the authoritative knowledge content stored by B19.

B19.8 determines which knowledge is relevant.

B19.9 assembles retrieved knowledge metadata into deterministic RAG context.

B19.10 defines the formal contract for handing that context toward future AI investigation.

B19.11 resolves the selected document identifiers back to authoritative knowledge content through the controlled `KnowledgeRepository`.

The purpose of this component is to ensure that future AI consumers receive authoritative knowledge content without allowing the AI layer to directly access or modify the underlying repository.

> **RAG determines relevant knowledge. B19.11 controls access to authoritative knowledge content. AI reasons over the supplied context. TAP controls authority and execution.**

B19.11 does not decide what an AI model should conclude.

It only resolves the knowledge that the deterministic RAG pipeline has already selected.

---

## 4. Why B19.11 Is Required

Earlier B19 components intentionally maintain a clean separation between retrieval metadata and authoritative document content.

B19.8 returns ranked retrieval results containing identifiers, metadata, scores, and provenance.

B19.9 packages those results into deterministic RAG context.

B19.10 formalizes that context for future AI consumption.

However, the assembled retrieval context does not itself provide unrestricted access to the complete underlying document content.

B19.11 closes that controlled boundary.

The resolver receives:

- an `AIContextRequest`
- selected document identifiers
- an authoritative `KnowledgeRepository`
- a configured maximum content size

It then returns the corresponding authoritative content in deterministic order.

This avoids introducing an uncontrolled secondary knowledge-access mechanism into the AI layer.

---

## 5. KnowledgeContentResolver

`KnowledgeContentResolver` is the B19.11 implementation boundary for controlled content resolution.

It accepts an `AIContextRequest` and an authoritative `KnowledgeRepository`.

For every document selected by the RAG context, the resolver:

1. Validates the incoming request.
2. Validates the repository dependency.
3. Retrieves the authoritative `KnowledgeDocument` by document ID.
4. Preserves the selected retrieval rank.
5. Copies authoritative document metadata.
6. Copies the authoritative document content.
7. Preserves provenance references and checksums supplied by the assembled context.
8. Enforces the configured maximum content-character limit.
9. Produces a deterministic `ResolvedKnowledgeContext`.

The resolver is read-only.

It does not add, modify, delete, rank, or regenerate knowledge.

---

## 6. ResolvedKnowledgeContent

`ResolvedKnowledgeContent` represents one authoritative knowledge item made available through the B19.11 boundary.

It contains:

- rank
- document ID
- title
- content
- source
- knowledge type
- source type
- resource
- incident ID
- version
- provenance reference
- provenance checksum

The object validates required identity and content fields and rejects invalid optional metadata.

The rank is preserved from the previously assembled RAG context rather than recalculated by B19.11.

This maintains the separation between retrieval/ranking and content resolution.

---

## 7. ResolvedKnowledgeContext

`ResolvedKnowledgeContext` is the controlled collection returned by B19.11.

It contains:

- request ID
- investigation ID
- investigation purpose
- resolved knowledge items
- maximum item count
- maximum content-character limit
- total resolved content characters

Validation guarantees that:

- request identity is present
- investigation identity is present
- purpose is present
- item count does not exceed the configured maximum
- ranks are sequential
- every item is a valid `ResolvedKnowledgeContent` object
- calculated content length matches `total_content_chars`
- total content does not exceed `max_content_chars`

This creates a deterministic and auditable content-resolution result.

---

## 8. Authoritative KnowledgeRepository Boundary

B19.11 treats `KnowledgeRepository` as the authoritative source for document content.

The resolver does not reconstruct content from retrieval metadata, search results, cached text, or AI-generated material.

For each selected document ID, it performs a controlled repository lookup.

This establishes a clear authority chain:

```text
RAG Selection
     |
     v
Document ID
     |
     v
KnowledgeRepository
     |
     v
Authoritative KnowledgeDocument
     |
     v
B19.11 ResolvedKnowledgeContent
```

If a selected document cannot be found, the repository lookup fails rather than silently substituting another document.

This behavior protects knowledge integrity and prevents silent content substitution.

---

## 9. Deterministic Resolution

B19.11 does not perform a second retrieval or ranking operation.

The order of resolved items follows the ranks already established by the upstream RAG context.

This means that identical validated inputs produce the same logical resolution order.

B19.11 therefore remains deterministic and independently testable.

The resolver does not introduce:

- semantic search
- keyword ranking
- embedding similarity
- model-generated ranking
- provider-specific behavior

Those concerns remain outside the content-resolution boundary.

---

## 10. Content Size Protection

B19.11 enforces a configurable `max_content_chars` limit.

Before each document is added to the resolved context, its content length is checked against the remaining available capacity.

If adding a document would exceed the configured limit, resolution fails explicitly.

This prevents an uncontrolled amount of authoritative knowledge from being assembled into a single AI context.

The final `total_content_chars` value is independently validated against the actual resolved content.

This provides a deterministic accounting check for the assembled knowledge payload.

---

## 11. Missing Knowledge Behavior

A selected document ID is expected to resolve to an existing `KnowledgeDocument` in the authoritative repository.

If the document does not exist, `KnowledgeRepository.get()` raises a `KeyError`.

B19.11 does not silently ignore the missing document, invent replacement content, or continue with an incomplete interpretation.

This fail-closed behavior is intentional.

For an AI-SRE investigation, missing knowledge should remain visible as a resolution failure rather than being converted into apparently valid context.

---

## 12. Provenance Preservation

B19.11 preserves provenance information already attached to the assembled RAG context.

The resolved content can carry:

- provenance reference
- provenance checksum
- source
- version

B19.11 does not create a new provenance claim for the document content.

The authoritative document remains the source of the resolved content, while provenance metadata remains traceable through the RAG pipeline.

This supports future auditability and evidence lineage.

## 13. Repository Immutability

B19.11 uses the repository as a read-only authority.

The resolver invokes repository retrieval operations only.

It does not:

- add documents
- remove documents
- modify documents
- rewrite document content
- alter repository metadata

This prevents the AI-context preparation stage from becoming an indirect knowledge-management interface.

Knowledge lifecycle operations remain separate from context resolution.

---

B19.11 contains no dependency on a specific AI provider or model.

The resolver produces structured knowledge content that can be consumed by any future AI investigation component through the established AI context contract.

It does not contain:

- provider-specific prompt formats
- model-specific APIs

This preserves the TAP architecture principle that models are replaceable intelligence providers while TAP remains the stable governance and authority boundary.

## 16. MCP Relationship

MCP may provide controlled evidence and tool access to TAP and future AI-SRE workflows.

B19.11 does not make MCP an authority mechanism.

MCP can expose information or tools, but consequential infrastructure authority remains with TAP governance, authorization, execution, verification, and recording.

This maintains the distinction between:

- information access
- AI reasoning
- authority
- execution

B19.11 belongs to the information and knowledge layer.

---

## 17. Security Boundary

B19.11 contributes to the security boundary by limiting content resolution to document IDs already selected by the deterministic RAG pipeline.

The component does not expose unrestricted repository enumeration to the AI consumer.

Content is resolved only through the supplied `KnowledgeRepository` and only for the context items contained in the validated request.

The configurable content limit provides an additional control against uncontrolled context expansion.

B19.11 should therefore be treated as a controlled read boundary rather than a general-purpose repository API.

## 22. Core AI-SRE Lifecycle Principle

> **Monitoring detects. Observability exposes system behavior. Evidence establishes what happened. RAG supplies relevant knowledge. AI investigates and reasons. TAP governs decisions and authority. Automation executes. Verification proves the result.**

B19.11 occupies the RAG knowledge stage of this lifecycle.

Its role is to ensure that knowledge selected by the deterministic RAG pipeline can be resolved into authoritative content before it reaches future AI investigation.

A practical TAP interpretation is:

- **Monitoring detects** a service or infrastructure signal.
- **Observability exposes** the behavior and relationships surrounding that signal.
- **Evidence establishes** what actually happened.
- **RAG supplies** relevant historical, procedural, architectural, and incident knowledge.
- **B19.11 resolves** the authoritative content selected by the RAG pipeline.
- **AI investigates and reasons** over the supplied evidence and knowledge.
- **TAP governs** what decisions and actions are permitted.
- **Automation executes** an authorized remediation.
- **Verification proves** whether the intended result was achieved.

B19.11 therefore strengthens the knowledge stage without crossing into AI authority or infrastructure execution.
