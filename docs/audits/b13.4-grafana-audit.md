## 1. Purpose

Grafana provides the visualization and operational dashboard layer for the Server B observability platform.

It consumes metrics from Prometheus and provides the foundation for:

- Kubernetes infrastructure dashboards
- Operational monitoring
- AI-SRE investigation dashboards
- Incident analysis
- Capacity and resource analysis
- Future correlation of metrics, logs, traces, and events

Grafana is a visualization and analysis interface. It does not directly execute infrastructure remediation.

---

## 2. Architecture

Current observability flow:

K3s
→ Prometheus
→ Grafana
→ Operator / AI-SRE investigation

Prometheus collects Kubernetes infrastructure metrics including:

- Kubernetes API server
- Kubelet
- cAdvisor
- CoreDNS
- kube-state-metrics
- node-exporter
- Prometheus
- Prometheus Operator

Grafana is deployed inside the K3s monitoring namespace.

## 4. Configuration

Configuration file:

    kubernetes/monitoring/grafana/values-grafana.yaml

Final configuration:

    persistence:
      type: pvc
      enabled: true
      storageClassName: local-path
      accessModes:
        - ReadWriteOnce
      size: 5Gi

    service:
      enabled: true
      type: ClusterIP
      port: 80
      targetPort: 3000

    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 500m
        memory: 512Mi

    datasources:
      datasources.yaml:
        apiVersion: 1
        datasources:
          - name: Prometheus
            type: prometheus
            url: http://prometheus-kube-prometheus-prometheus.monitoring.svc.cluster.local:9090
            access: proxy
            isDefault: true
            editable: true

The configuration is declarative and stored in Git.

## 16. Recovery Considerations

Grafana configuration is stored in Git:

    kubernetes/monitoring/grafana/values-grafana.yaml

The Grafana Helm release can therefore be recreated from the repository.

The Grafana PVC contains runtime state and should be included in future backup procedures.

Current local-path storage should not be considered equivalent to a production-grade off-host backup.

## 17. Lessons Learned

### 17.1 Helm chart migration

The original Grafana chart reference under prometheus-community was no longer available.

The deployment was corrected by using:

    grafana-community/grafana

### 17.2 Chart schema inspection

The chart values were inspected before final configuration.

Important lesson:

    Do not assume Helm value nesting.
    Inspect the actual chart schema before deployment.

### 17.3 Declarative datasource configuration

The Prometheus datasource was configured declaratively through Helm values instead of manually configuring Grafana through the web interface.

This improves:

- Reproducibility
- GitOps compatibility
- Recovery
- Auditability
- Portability
